# Соответствие теме практики СФУ — FitProgress

**Источник:** файл преподавателя «Темы 2025.docx», раздел «Темы 2026», тема «Веб-приложение для учёта и анализа спортивных тренировок», последняя страница (32). Ниже названия и порядок семи функциональных требований воспроизведены из документа.

| № | Требование преподавателя | Реализация в FitProgress | Проверка |
|---|---|---|---|
| 1 | Создание тренировки: дата, вид спорта, список упражнений с подходами (вес, повторения, время) | Journal, создание/редактирование/удаление, PostgreSQL | API integration, UI проверяется вручную |
| 2 | База упражнений с группой мышц и описанием техники, возможность добавить своё | Exercises, встроенный список и пользовательские записи | API integration |
| 3 | График прогрессии по выбранному упражнению: максимальный вес и объём по датам | Analytics, выбор упражнения и переключатель «Макс. вес / Расчётный объём» | Unit test for progression; UI manual check |
| 4 | Личные рекорды (PR) по каждому упражнению с датой установки | Analytics, датированные личные показатели по всем упражнениям, включая упражнения без дополнительного веса | Unit test for records; UI manual check |
| 5 | Расчёт недельного тренировочного объёма по группам мышц | Analytics, 7 последних дней, выбор отображения расчетного объёма по мышцам | Unit test for muscle aggregation |
| 6 | Шаблоны тренировок: сохранить тренировку как шаблон и запустить повторно | Journal -> Save Template, Templates -> Use to prefill a new workout | API integration, UI manual check |
| 7 | Сравнение текущего месяца с предыдущим: количество тренировок, суммарный объём, средняя продолжительность | Analytics, количество, расчётный объём (отдельно от реального веса), средняя продолжительность | Unit test for comparisons |

**Стек из задания:** React, TypeScript, Fastify, PostgreSQL, Recharts — используется без замены.

**Дополнительно:** регистрация и вход пользователей, разграничение данных, выбор языка RU/EN, журнал измерений веса тела (необязательный). Дополнительные функции не следует представлять как обязательное требование преподавателя.

## Границы проверки

- Наличие реализации — не то же самое, что подтверждение полной корректности в реальном браузере. До сдачи выполните ручные сценарии от двух разных аккаунтов и сохраните подтверждения тестов.
- Перед публичным запуском требуется production-инфраструктура: защищённая размещённая база данных, постоянно доступное API или корректный serverless адаптер, HTTPS, корректные защищённые cookie и конфигурация origin, политика резервного копирования. Не направляйте пользовательские данные на демонстрационную локальную БД.
- В проекте упрощённая модель упражнений. Для упражнений без дополнительного веса личным показателем служат повторения или длительность; расчётный объём по весу учитывает только подходы с весом.
- Шестой пункт реализован как предварительное заполнение новой записи из шаблона, которую пользователь должен сохранить, а не как автоматическая фиксация готовой тренировки.
